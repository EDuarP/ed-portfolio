## 📖 About

A fast, dependency-free single-page portfolio that presents Eduardo Duarte's profile, featured
projects, technical skills and CV. Built with plain HTML, CSS and vanilla JavaScript — no
frameworks, no build step — and deployed on GitHub Pages.

The site is being redesigned around a **dark bento layout** with a futuristic **"HUD" bracket style**,
fully bilingual (ES / EN) and focused on **freelance clients**. Featured projects are
[Portal Madre Tierra](https://madretierragroup.co) and
[Nest – Finanzas en Pareja](https://play.google.com/store/apps/details?id=com.nestapp.nest_app) (Google Play).
The contact area is a **brief builder**: the visitor describes their project and the site prepares a
ready-to-send WhatsApp or email message.

The site targets an audience in both English and Spanish and focuses on:

- **Machine Learning & AI Engineering** — end-to-end ML/AI systems, from data to production
- **Cloud** — Microsoft Azure & AWS
- **Data Science & Analytics**
- **IoT & hardware/software integration**
- **Software engineering**

## ✨ Features

- 🌐 **Bilingual UI (EN / ES)** — instant language switch driven by a lightweight `data-i18n` dictionary, no page reload
- 🖼️ **Image lightbox** — click any project image to open a full-screen gallery with previous/next and keyboard navigation (`← → Esc`)
- 🧱 **Dark bento + HUD brackets** — modular card layout with a futuristic, bracketed look
- ✉️ **Brief builder** — turns a few answers into a prepared WhatsApp / email message
- 📱 **Responsive layout** — adapts from mobile to desktop
- ⚡ **Zero dependencies / zero build** — pure static site, loads instantly
- 🧩 **Skills grid** with recognizable tech icons
- 📄 **One-click CV download**

## 📄 CV generator

The CV is generated from data, so it never has to be edited by hand in a layout tool. Everything
lives in `cv/`: `cv/cv.yaml` holds the content and `cv/build.py` renders it to LaTeX (moderncv,
banking style) and compiles it to PDF.

**Data (`cv/cv.yaml`)**

- Inline formatting in any text: `**bold**`, `*italic*` and `[text](url)` for links.
- `sections` render in the order they appear. Each section has a `title` and a `type`:
  - `paragraph` — a single block of `text`
  - `entries` — jobs / studies with `org`, `location`, `role`, `dates`, optional `note` and `items` (bullets)
  - `items` — `label` + `text` rows (e.g. skills)
  - `lines` — plain lines of text
- An entry **without `org` / `location`** renders as another role at the same company as the entry above it.
- Quote any YAML string that contains `": "` (colon + space), otherwise YAML reads it as a mapping and the build stops with an error.

**Build**

```bash
python cv/build.py                  # cv/cv.yaml -> Eduardo_Duarte_CV.pdf (repo root)
python cv/build.py cv/cv.es.yaml    # use another data file (e.g. a Spanish version)
python cv/build.py --tex-only       # only write cv/build/Eduardo_Duarte_CV.tex (e.g. to compile in Overleaf)
```

Requirements: Python 3 with PyYAML, and [Tectonic](https://tectonic-typesetting.github.io) on your
`PATH` (a single-binary LaTeX engine). If Tectonic is missing, the script falls back to `latexmk` or `xelatex`.

The PDF is written to `Eduardo_Duarte_CV.pdf` at the repo root, which is the file the website links.
That PDF stays tracked in git; the intermediates in `cv/build/` are ignored via `.gitignore`.
